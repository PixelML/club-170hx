**Question.** PR #90 got `thinkingmachines/Inkling-2-Mini` running on SM80 with six minimal compatibility patches (`108.56 tok/s` 6-prompt median / `146.0 tok/s` code on a stock CMP 170HX, `491.1 tok/s` at `c=16`, `432.5 s` cold startup, `32,768` context). How far can a stock-clocked CMP 170HX (`1,140 MHz` SM / `1,728 MHz` HBM2e, strict `140.00 W` TDP, `1,600.5 GB/s` D2D copy bandwidth) push single-user decode, `c=16` throughput, and full `262,144`-token context (including 13-group coalesced `809,126`-token `3.09x` FP8 KV) from one unified server without changing the target output distribution?

**Answer (measured): `108.56 → 134.98 → 155.48 → 164.25 → 167.24 → 171.84 tok/s` median (`+58.3%`, beating flanking controls on 6/6 prompts) single-user decode and `491.1 → 710.25 tok/s` (`710.91` peak, `+44.6%` / `+44.8%`) `c=16` aggregate on the same unified server at full `262,144` context.** On PR #90's exact benchmark harness (`harness/bench.py`, 768 output tokens) at `262,144` context on the stock card, Round-5 Best reaches **`218.9 tok/s` code (`233.2` at `T=0`, `233.4` peak), `203.7 tok/s` structured JSON (`221.0` `T=1` median, `231.0` peak), `131.5 tok/s` prose (`135.0` peak), and `666.4 tok/s` at `c=16`** (`313.0 tok/s` JSON extraction / `237.6 tok/s` mean on the agentic suite) — beating PR #90's stock-card baseline (`146.0 / 136.8 / 87.5`) by `+49–50%` and PR #90's `+200 MHz SM offset` card at `32K` context (`166.9 / 189.1 / 94.0` at `T=0`, `510.9` at `c=16`) by `+39.7%` code (`T=0`), `+39.9%` prose, and `+30.4%` (`+39.0%` unified) at `c=16`. Long-context needle retrieval is **`3/3` at `131,227` tokens (`218.44 tok/s` decode, `+12.5%` over Round 4) and `231,044` tokens (`165.65 tok/s` decode, `+19.5%` over Round 3)**, and propagating `cache_config` into DSpark's attention coalesces **`--kv-cache-dtype=fp8` from `99 → 13` KV groups**, lifting FP8 `c=1` short decode **`121.62 → 162.59 tok/s` (`+33.7%`)**, `c=16` to **`701.47 tok/s` (`710.91` peak)**, and the `262K` KV pool to **`809,126` tokens (`3.09x`)**, passing **`4 × 172.0K` = `689,445` simultaneous active KV tokens in `407.6 s` (`4/4` streams, `12/12` needles, `0` errors)** and **GSM8K-50 `50/50` (`100%`)** (`49/50 = 98%` on BF16-KV).

## Winning stack summary

1. **Universal `0-ULP` (`torch.equal == True`) 140 W Cold-HBM SM80 Humming v5 MoE buckets (`patches/overlay/nvidia/ops/moe_sm90.py`):** 8-warp `num_warps_k=1` `[8, 128, 64] w=[8, 32, 64] stg=5 cta=3 evict=False` on `NVFP4 w13 (16, 256]` (`-0.461 ms/step`, `0-ULP`), `[8, 256, 128] w=[8, 64, 64] stg=4 cta=2 evict=True` on `NVFP4 w13 (256, 912]` (`0-ULP` across prefill & `c=16`), `[8, 128, 128] w=[8, 64, 64] stg=3 cta=3 evict=True` on `NVFP4 w2 (16, 256]`, `stg=4 cta=3` `[8, 128, 64]` on `MXFP8 w2` (`1.553 → 0.863 ms`), plus restored `BM=96` prefill buckets above `2,048` rows.
2. **Custom SM80 CUDA megakernels (`patches/sm80_fast_v6.cu`, `patches/overlay/sm80_ops_v2.py`, 0 spills):** compiled inside the container with `nvcc -O3 -arch=sm_80 --shared -Xcompiler -fPIC` (`moe_align_v3_sm80`, `select_and_align_32cta_128_sm80`, `<1 KB`-smem `conv_mix_2304_sm80`, `swiglu_1152_sm80`, `pair/blend_rms_norm_2304_sm80`, `markov_rnn_gate_256_sm80`, and 1-launch bitwise-exact `markov_fold_gumbel_cache_r1_sm80` + opt-in `OnlineAcceptanceEstimator` & HBM-ring SuffixDecoding kernels).
3. **SM80 low-M Tensor-Core linears & FA2 vision (`patches/overlay/nvidia/ops/ll_gemm_sm80.py` + `nvidia/{model.py,vision.py}`):** ported & retuned `_ll_gemm_kernel` + 1-launch `_qkv_bmm_kernel` from `vllm` PR `#69168` (`BN=128` `8600×2304` `loc_qkvr`, batched `MP=64` `loop.blend`, `cuBLAS` `M>=5` `lm_head`), plus SM80 FA2 routing for the 23-layer ViT vision encoder.
4. **Lossless DSpark `K=49,152` pruning + zero-scatter `-inf` `DraftLogitsCache` + bidirectional `k=4` + joint block verification (`"block"`) + dynamic batch `k` (`[[1,2,4],[3,6,3],[7,256,2]]`):** `fold_weight` shrinks `102.9 → 25.17 MB` (fits inside the `32.0 MiB` physical L2 cache); `k=4` concentrates DSpark bidirectional block attention; Sun et al. joint block verification lifts prose `+13.3%`; dynamic `k` unifies `c=1` (`k=4`) and `c=16` (`k=2`) in one server.
5. **Monolithic `M <= 21` FULL CUDA graphs + slots-safe Sconv metadata deduplication + 18-split SM80 global decode attention + 13-group coalesced SM80 E4M3 FP8 KV (`patches/overlay/nvidia/{attention.py,dspark.py}` + `nvidia/ops/{attention.py,attention_sm90.py,sconv.py}`):** eliminates piecewise graph breaks across all 48 layer visits, deduplicates `sconv_seq_metadata` from `6 → 1` Triton launch/step, raises global decode `head_splits` `9 → 18` (`1,329.8 GB/s` = `89.1%` raw HBM2e peak; `218.44 / 165.65 tok/s` @ `131K / 231K`), and propagates `cache_config` into DSpark so `--kv-cache-dtype=fp8` coalesces from `99 → 13` KV groups (`809,126` KV tok = `3.09x` @ `262K`, `162.59 tok/s` `c=1`, `701.47 tok/s` `c=16`, `50/50` GSM8K-50).
